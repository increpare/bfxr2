# Neural v2 implementation plan

> Use superpowers:subagent-driven-development for the isolated data task and
> spec/code reviews. User authorization covers design and routine execution.

**Goal:** Train and run an improved acoustic inverse model, validate it across
engines, then provide five useful quick judgments when human input is needed.

**Architecture:** Immutable augmented shards, backward-compatible acoustic heads,
explicit supervised acoustic-control loss, existing actual-DSP inference/search,
and independently rendered evaluation followed by an immutable listening run.

**Tech stack:** Python, PyTorch/MPS, shipped JavaScript DSP worker, NumPy, Web Audio.

- [x] Data implementer owns `neural_invert/structured.py` and
  `test_neural_structured.py`. Add deterministic structured draws and augment
  existing shards while preserving originals and re-splitting duplicate groups.
  Verify invalid/resume/config/file integrity, canonical codec and actual render.
  Generate `runs/neural-v2/data` from v1 with 2,048 added rows for three engines.
- [x] Root owns model/train/predict and new acoustic-loss tests. Preserve default
  v1. V2 head outputs must remain identical under changed generator ancestry.
  Test log-frequency octave penalty and inactive-control masking, finite gradient,
  checkpoint reload/mode compatibility and distinct categorical proposals.
- [x] Train data-only generator-conditioned baseline and acoustic v2, fixed seed,
  30 epochs each, held-out loss checkpoint selection, existing venv and MPS.
  `PYTHONPATH=tools python -m neural_invert.train --data ... --output ... --epochs 30`
- [ ] Evaluate raw source-head and best rendered experts against frozen v1 with
  fresh pitches/gestures and fresh generator controls for all 22 engines. Save
  every candidate score, voicing failure and missing case. Check exact exclusions.
- [x] Audit human preference/objective disagreements and try fixed grouped
  preference refit on all retained archives. Keep baseline/default unless evidence
  supports the change. Publish reports with reference-group limitations.
- [x] Spec review, then code quality review; fix all important findings and run
  focused old/new neural tests plus actual DSP/audio replay checks.
- [ ] Render new five-reference tagged listening experiment with original Bfxr
  and exact preferred previous clips, bind all provenance, quick UI, localhost/LAN
  links, browser check on a separate origin. Document CLI and measured results,
  commit code/reports; stop at the necessary human listening check.
