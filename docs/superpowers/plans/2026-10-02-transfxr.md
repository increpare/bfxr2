# Transfxr Implementation Plan

**Goal:** Complete and expose Transfxr with usable transitions and enjoyable examples.

**Architecture:** Keep the existing SynthBase/Tab/RealizedSound interfaces. Add a pure Transfxr_DSP renderer; store each transition as an independently copied `{start, end, curve}` object. Use directly editable SVG graphs, accessible endpoint handles and curve-shape buttons.

**Tech Stack:** Plain JavaScript, Web Audio PCM buffers, Node's built-in test runner.

- [x] Add failing tests in tests/transfxr.test.js for state copies, locks, transitions, rendering and save compatibility. Run `node --test tests/transfxr.test.js` and confirm missing functionality.
- [x] Complete transition support in js/synths/SynthBase.js (defaults, normalization, setters, randomize/mutate, template bounds).
- [x] Add js/audio/Transfxr_DSP.js: bounded curves, phase-continuous oscillators, swept resonant low-pass, deterministic noise, envelope and echo. Replace js/synths/Transfxr.js placeholders with controls and curated recipes.
- [x] Complete transition widgets in js/Tab.js and matching CSS; update state, display values/curve, persist edits and regenerate stale audio for export.
- [x] Register the tab and renderer in js/index.js and index.html. Support nested link values and absent collection sections in js/SaveLoad.js.
- [x] Run Node tests, render example WAVs and a .bcol, document controls. Exercise browser playback, editing, locks, persistence, links and exports plus existing synths. Review diff and fix any defects before delivery.
