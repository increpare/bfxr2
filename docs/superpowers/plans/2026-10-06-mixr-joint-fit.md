# Joint Mixr fitting plan

**Goal:** After the four-trial human rejection of convincing composition transfer, test whether co-adapting source controls helps external reproduction more than equally budgeted single-source search.

**Design and alternatives:** Retain the actual shipped Mixr renderer and old source identities. Simply enlarging native training or distilling least-bad real fits would not address the lack of adequate teacher candidates. Training an unverified surrogate would repeat a failed approach. Instead, jointly search source controls and balance with actual DSP; use single-voice search as an equal-budget control. This is an optimizer/candidate-generation experiment, not a new neural model or a claim that lower loss means likeness. User's standing autonomous authorization covers implementation without another design approval.

**Frozen experiment:** Same four external development references from the latest exact feedback archive. Two structures (one voice and two voices), each with two frozen scorers (soft-periodicity and preference-neural-v2). Each arm starts from the best four distinct source-engine signatures from the prior actual Mixr pool under its scorer, with fallback to distinct patches if needed. Each performs exactly 512 mutation attempts plus initial/final verification renders; preserve every incumbent. Numeric/categorical source controls can change; synth identities, random seeds, gain convention, and text remain fixed. Two-voice balance stays .1–.9. No added delays or reference audio layers. Single and pair arms have equal search attempts, not equal model capacity or wall time.

**Files/tasks:**
- Archive unchanged feedback and exact PCM, validate all four judgments, store one strict pair and ten qualitative labels. Preserve contradictory cross-session labels.
- Add `tools/multisynth/joint_refine.py`: decode Mixr source snapshots; mutate supported source controls using existing ControlSpace; immutable input, bounded balance, fixed seeds. Add tests for both source slots, one-source mode, deterministic replay, invalid inputs, budget and incumbent retention.
- Add `tools/multisynth/evaluations/mixr-joint-v1.py`: freeze code/metric/report/archive/spec hashes; run four independent reference jobs, each containing all four arms. Store final patches, exact waves, failures, monotonic traces, actual native replay, and all scorer measurements.
- Export eight short trials (four references × two scorers), up to three options each: exact retained earlier choice, equally budgeted single-source winner and pair winner, deduplicated by audition PCM. The existing quick UI presents three options; preserve that low-friction limit rather than hiding additional candidates. For prior ties/none retain the exact previous-role clip; these are controls, not inferred human winners. Ask adequacy in the existing quick UI. Include every fixed case regardless of numerical outcome.
- Verify native replay, frozen bindings, displayed candidate counts, no invented feedback, HTTP bytes; document the human outcome and numerical limits. Commit own files only.

**Verification commands:** `PYTHONPATH=tools .../python -m pytest tools/tests/test_joint_refine.py tools/tests/test_multisynth_quick_feedback.py -q`; `node --test tests/composition-context.test.js`; immutable feedback reimport; `mixr-joint-v1.py freeze`, `run`, `gallery`; served-file audit. Existing renderer and published pages must remain unchanged. No fitting on these human labels and no parameter checkpoint promotion.
