# Tagged candidate coverage diagnostic

Goal: distinguish poor inverse proposals from insufficient synth coverage after five tagged judgments yielded one similar winner and four least-bad winners. The standing user instruction authorizes autonomous experiments; preserve original models and exact human evidence.

Use the five already judged tagged references as development cases, with their exact preferred audio as the comparison anchor. They are not held-out validation. This diagnostic cannot establish a synth's absolute expressive limit.

1. Archive the complete schema-3 feedback; recompute heard-only preferences and immediate adequacy. No scalar labels, no adequacy for unassessed alternatives.
2. Freeze a retrieval protocol before inspecting its outputs. Use optimization rows only from the certified shared22 data and the two specialist fit-data sets. Exclude validation and test rows. Query the already generated 4,083-feature descriptors, then render retrieved controls through actual DSP. Verify manifests, schemas, source hashes, feature identity and every selected row's original raw audio hash.
3. For each engine/data set, retrieve the top four by equal normalized nine-group descriptor MSE and top four by the same score excluding pitch and voicing groups (six groups). Normalize using that data set's optimization rows, std floor .025. Ignore peak gain. This second route is an exploratory candidate proposal mechanism, not a change to tonal accuracy requirements or a deployed loss. Do not use filenames/tags to route engines.
4. Score every distinct retrieved control with the unchanged matching objective and frozen preference-neural-v2. Compare with all 295 retained neural raw/refined/original candidates from tagged-v1. Never use human adequacy to tune numeric weights or fabricate improvement.
5. Allocate four 128-mutation starts per target: two distinct retrieved engines by matching distance and two distinct retrieved engines by learned preference distance. Each arm retains its starting candidate; randomness is fixed. This is added candidate/search coverage, not equal-compute evidence or new neural training. Score exact single-normalization PCM16 audition audio. Preserve all returned candidates and actual render counts.
6. Before showing another batch, require novel control/audio candidates and numerical improvements over each target's exact human winner on at least one frozen scorer. Show up to five qualifying targets including disagreement cases. A numerical gate just avoids unchanged samples; only listening can establish likeness. Keep the exact previous human winner, new matching-scored alternative and new preference-scored alternative, deduplicated; use two choices when both select the same audio. Never ask the user to rerate an unchanged-only trial.
7. Independently verify reference/archived winner PCM, candidate rendering, model/data/source hashes, selectors and visible questionnaire options, then verify HTTP files. Report scope and numerical failures honestly. Preserve evidence and request the short quality check only after those checks pass.

Implementation files: `evaluations/specialists-tagged-quick-01-human-review.py`, `evaluations/tagged-coverage-v1.py`, and a separate gallery/audit exporter. Runs go in a new ignored `runs/tagged-coverage-v1` directory. No production inference, descriptor or UI changes. Do not retrain on pseudo-labels before establishing that these proposed teachers are audibly useful.
